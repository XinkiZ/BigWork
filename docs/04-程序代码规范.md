# 学生选课注册系统 程序代码规范

**文档版本**：V1.0（2026-10-15 定稿）　**编写**：成员E　**评审**：成员A（组长）、全组
**适用范围**：`backend/`（Java 21 + Spring Boot）、`frontend/`（Vue3 + Vite）、`db/`（SQL）、`tools/`（Node 脚本）

---

## 1 目的
统一 6 名成员的编码风格与接口风格，使代码在被他人接手时可读、可改、可评审；同时把
"错误码""分层边界""命名"这些最容易在并行开发中失控的点固化为可检查的规则。

---

## 2 工程结构约定

### 2.1 后端包结构（`com.wylie.registration`）
```
RegistrationApplication.java      启动类
common/      统一错误码、业务异常、错误响应体、全局异常处理
config/      数据源、缓存、属性配置类（Legacy/Billing/Tuition/Web）
domain/      实体与枚举（与数据库表一一对应）
repo/        Spring Data JPA 仓储接口（每个实体一个）
security/    JWT 服务、认证过滤器、AuthUser、安全配置
legacy/      遗留目录适配器与中间层（Adapter / CatalogService / Snapshot / 只读异常）
service/     业务服务（每个业务域一个类）
web/         REST 控制器
web/dto/     请求/响应数据传输对象（record 优先）
```

### 2.2 前端目录
```
src/api/        http.js（Axios 实例与拦截器）、index.js（按域分组的接口封装）
src/components/ Win95* 通用组件（不含业务逻辑）
src/router/     路由与角色守卫
src/stores/     Pinia 状态（auth=登录态、ui=弹窗）
src/styles/     win95.css 主题
src/views/      页面，按角色分子目录（student/ professor/ registrar/）
src/App.vue     桌面外壳、菜单、任务栏、全局对话框
```

### 2.3 依赖方向（禁止反向依赖）
`web → service → repo → domain`；`service → legacy`；`service → security(AuthUser)`。
- **Controller 不得直连 Repository**，也不得写业务规则。
- **Repository 不得被 web 层或 legacy 层引用**。
- `common` 与 `domain` 不依赖任何上层包；`legacy` 不依赖 `service`。

## 3 命名规范

### 3.1 Java
| 元素 | 规范 | 示例 |
|------|------|------|
| 类 / 接口 / 枚举 | 大驼峰 | `ScheduleService`、`CourseOfferingView`、`OfferingStatus` |
| 方法 / 变量 | 小驼峰 | `adjustmentAdd`、`enrolledCount`、`currentSemester` |
| 常量 / 枚举值 | 全大写下划线 | `MAX_PRIMARY`、`REGISTERED`、`PREREQUISITE_NOT_MET` |
| 布尔量 | 用 `is`/`has`/`can` 前缀或形容词 | `isCached()`、`full`、`promoted`、`hasData` |
| 包名 | 全小写 | `com.wylie.registration.legacy` |
| DTO | `XxxRequest` / `XxxView` / `XxxDto` / `XxxRow` | `ScheduleSubmitRequest`、`CourseOfferingView`、`RosterRow` |
| 表/字段（SQL） | 全小写下划线 | `course_offering`、`min_students`、`last_attempt_at` |

约定：业务上限常量集中在服务类顶部（如 `MAX_PRIMARY = 4`、`MAX_BACKUP = 2`），
禁止在方法内散落魔法数字（`10`、`3`、`500` 分别固定为容量、最少人数、每学分单价的配置项）。

### 3.2 Vue / 前端
| 元素 | 规范 | 示例 |
|------|------|------|
| 组件文件与组件名 | 大驼峰，`Win95` 前缀表示通用组件 | `Win95Window.vue`、`StudentWorkbench.vue` |
| 页面文件 | 业务语义 + 大驼峰，放在角色目录下 | `views/student/ScheduleView` 用途的 `StudentSchedule.vue` |
| 组合式函数 | `use` 前缀 | 预留 `useDialog()` 风格扩展 |
| Pinia store | `useXxxStore` | `useAuthStore`、`useUiStore` |
| API 分组 | 小驼峰 + `Api` 后缀 | `authApi`、`studentApi`、`registrarApi`、`systemApi` |
| CSS 类 | 主题类用 `w95-` 前缀，页面类用语义名 | `.w95-button`、`.w95-titlebar`、`.catalog-table` |

## 4 统一错误码规范

后端所有业务失败必须抛出 `BusinessException(code, message[, httpStatus])`，由
`GlobalExceptionHandler` 统一转换为 JSON 错误体 `{ "code": ..., "message": ... }`。
**禁止**在 Controller 中 `try/catch` 后返回拼接字符串，**禁止**新增未登记的错误码。

| 错误码 | 含义 | HTTP | 出现场景（示例） |
|--------|------|------|------------------|
| `UNAUTHORIZED` | 未登录 / 令牌无效 | 401 | 未携带或伪造 JWT；登录口令错误 |
| `FORBIDDEN` | 已登录但无权限 | 403 | 学生访问教授接口；教授录入他人课程成绩 |
| `NOT_FOUND` | 目标对象不存在 | 404 | 学生/教授 ID 不存在；课程班不存在；无课表可删 |
| `VALIDATION` | 请求参数不合法 | 400 | 缺少姓名；主选超过 4 门；备选超过 2 门；成绩等级非法 |
| `METHOD_NOT_ALLOWED` | 请求方法不被支持 | 405 | 对只支持 PUT 的接口发起 GET |
| `STATE_ERROR` | 业务状态不允许该操作 | 409 | 重复关闭注册；不在调整期；课程班已取消；非上学期成绩录入 |
| `REGISTRATION_CLOSED` | 注册已关闭 | 409 | 关闭后仍尝试选课或调整授课 |
| `PREREQUISITE_NOT_MET` | 先修课程未满足 | 409 | 提交课表时缺先修课 |
| `COURSE_FULL` | 课程班已满（实时通知） | 409 | 已选人数达到容量 10 |
| `TIME_CONFLICT` | 上课时间冲突 | 409 | 课表内两门课时间重叠；教授授课冲突 |
| `DUPLICATE_COURSE` | 重复选择同一课程 | 409 | 同一课程的不同课程班被同时选入 |
| `CATALOG_UNAVAILABLE` | 课程目录系统不可用 | 503 | `legacy.available=false` 或遗留库连接失败 |
| `BILLING_UNAVAILABLE` | 计费系统不可用 | 503 | 计费开关关闭时的即时发送失败 |
| `INTERNAL` | 未预期异常 | 500 | 兜底（日志记录完整堆栈） |

规则：
1. 错误消息面向最终用户，必须是**中文 + 可操作建议**（例如"课程已满，请启用备选课程"）。
2. 客户端分支判断一律基于 `code`，不解析 `message` 文本。
3. 新增错误码需同步更新本规范与《接口文档》。
4. 框架级异常（不存在的路径、不支持的请求方法、参数类型不符、请求体不可解析）由 `GlobalExceptionHandler` 统一转换为 `NOT_FOUND`(404) / `METHOD_NOT_ALLOWED`(405) / `VALIDATION`(400)，**不得落到 500 兜底**。

## 5 REST 接口约定

| 项 | 约定 |
|----|------|
| 前缀 | 所有业务接口以 `/api` 开头，后接角色域：`/api/auth`、`/api/student`、`/api/professor`、`/api/registrar`、`/api/system` |
| 数据格式 | 请求与响应均为 `application/json; charset=UTF-8`；请求体 DTO 用 record + `@Valid` 校验 |
| 方法语义 | `GET` 查询（无副作用）、`POST` 创建/触发动作、`PUT` 整体更新、`DELETE` 删除/取消 |
| 资源命名 | 复数名词表示集合（`/students`、`/offerings`、`/billing-transactions`）；动作型操作以子路径表示（`/close-registration`、`/adjustment/add/{id}`） |
| 身份传递 | 一律通过 `Authorization: Bearer <token>`；**不允许**在 URL/请求体中传学生 ID 以"代为操作" |
| 时间格式 | 日期 `yyyy-MM-dd`；时刻 `HH:mm`；时间戳 `yyyy-MM-ddTHH:mm:ss`（ISO-8601 字符串） |
| 列表返回 | 直接返回 JSON 数组；空结果为 `[]`，前端展示"无数据"提示 |
| 错误返回 | 统一 `{ "code": "...", "message": "..." }`（见第 4 节） |
| 状态码 | 200 成功（含删除返回 `{code:"OK", message:"..."}`）、400/401/403/404/409/503 与错误码一一对应 |

示例（成功）：
```json
{ "code": "OK", "message": "课表已删除，并已从对应课程班移除" }
```
示例（业务失败）：
```json
{ "code": "COURSE_FULL", "message": "《操作系统》课程班已满（10/10），请启用备选课程或选择其他课程班" }
```

## 6 注释与文档规范

1. 类级 Javadoc 必须说明**业务含义**与对应的用例/业务规则（例如
   "课程注册（Register for Courses）核心服务……覆盖主选 4 + 备选 2"）。
2. 复杂算法（备选补位、时间冲突判定、循环收敛）必须写清**为什么这样做**，而非重复代码字面意义。
3. 前端每个组件顶部用注释说明"这个窗口/表格展示什么、数据来自哪个接口"。
4. 注释语言统一中文；不写"TODO 待补"式的空注释；不保留被注释掉的死代码。
5. 提交前删除调试用 `console.log`/`System.out.println`（日志统一用 `Logger`）。

## 7 前端编码规范

1. **组件职责单一**：通用组件（`Win95*`）不含任何业务 API 调用；业务数据获取只在页面组件中完成。
2. **状态管理边界**：跨页面共享状态（登录态、弹窗）进 Pinia；页面内临时状态用 `ref/reactive`。
3. **接口调用**：一律通过 `src/api/index.js` 暴露的函数，禁止在组件中直接 `axios.get('/api/...')`，
   以保证 JWT 注入、401 广播、错误提示风格统一。
4. **错误处理**：捕获接口错误后，使用 `uiStore.alert(message)` 以 Win95 对话框呈现；
   展示 `code` 相关的中文提示，不直接抛出原始异常。
5. **二次确认**：删除学生、删除教授、删除课表等破坏性操作必须调用 `uiStore.confirm(...)`，
   用户取消则不发起请求（对应用例"取消删除 → 状态不变"）。
6. **样式**：禁止内联样式堆叠（可用少量动态样式绑定）；新增样式写入 `win95.css` 或使用 `scoped`；
   颜色只取自主题色板（灰 `#c0c0c0`、深蓝 `#000080`、白/黑描边），保持 95/98 观感一致。
7. **文案**：界面、按钮、提示全部中文；按钮使用"确定/取消/保存/关闭/刷新"等规范词。

## 8 数据库脚本规范

1. 脚本必须**幂等**：以 `DROP DATABASE IF EXISTS` + `CREATE DATABASE` 重建，可反复执行恢复基线。
2. 字符集固定 `utf8mb4` / `utf8mb4_general_ci`；表与字段注释使用中文 `COMMENT`。
3. 字段命名 `snake_case`；状态字段用**英文常量**（`OPEN/CLOSED`、`DRAFT/SUBMITTED`、
   `SELECTED/REGISTERED/REMOVED`、`PENDING/SENT/FAILED`）并在注释中给出取值含义。
4. 主库建外键约束；**遗留库刻意不建外键**（保持遗留风格，不得为了"整洁"改变该特征）。
5. 账号与授权：应用账号 `bigwork_app` 对 `bigwork`/`bigwork_test` 授权；遗留库账号 `legacy_ro`
   **仅 `SELECT`**。root 口令不写入任何脚本或文档。
6. 种子数据需覆盖演示剧本所需的边界：满员班、不足 3 人班、无教授班、时间冲突对、
   先修链、上学期成绩（含未录入成绩的学生）。

## 10 提交与评审规范

### 10.1 提交（Commit）粒度
- 一次提交只做一件事（实现一个用例 / 修复一个缺陷 / 更新一份文档）。
- 提交信息格式：`<域>: <做了什么>`，例如 `注册核心域: 实现关闭注册备选补位与二次取消`、
  `课程目录域: 增加 Caffeine 缓存与 direct/cached 切换`、`文档: 补充接口文档错误码表`。
- 不提交编译错误、不提交未通过自测的代码；不提交本地环境文件（口令、日志、`target/`、`node_modules/`）。

### 10.2 自检清单（提交前逐条确认）
- [ ] 命名符合第 3 节；无魔法数字；无死代码与调试输出。
- [ ] 业务失败抛出的是登记过的错误码，消息为中文且可操作。
- [ ] 新增/修改接口已在《接口文档》同步。
- [ ] 破坏性操作有二次确认；越权路径返回 403。
- [ ] 涉及的数据库变更已更新 `db/init.sql` 且脚本可重复执行。
- [ ] 相关测试通过（`mvn test`）或说明未执行原因。

### 10.3 评审重点（走查人）
1. 业务规则是否与需求一致（主选/备选上限、容量 10、最少 3、先修、时间冲突、注册关闭）。
2. 事务边界是否正确（关闭注册必须单事务；计费发送不得拖入主事务）。
3. 是否误把遗留库当可写库使用；是否绕过了中间层直连遗留库。
4. 前端是否统一走 `api/index.js`、是否使用 `uiStore.confirm` 做删除确认。
