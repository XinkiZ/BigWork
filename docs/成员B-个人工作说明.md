## 3 关键设计取舍
| 取舍 | 理由 |
|------|------|
| 自研组件库而非引入第三方 UI 库 | 题目要求"界面符合 Windows 95/98 交互规范"，现成组件库的现代观感反而需要大量覆盖；自研约 300 行主题 CSS 即可精确控制 |
| 401 用事件广播而不是在拦截器里直接跳路由 | 拦截器里拿不到 router 实例（循环依赖风险）；广播事件后由 `App.vue` 统一处理，职责清晰 |
| 弹窗做成 Promise 型服务 | 删除确认需要"等用户回答"，Promise 化后业务代码 `if (!await confirm(...)) return` 即可，避免层层回调 |
| 所有接口集中在 `api/index.js` | 便于统一维护路径与字段，配合《接口文档》交叉核对，也便于后续替换实现 |
| 学期选择统一用 `SemesterSelect` | 各页面口径（全部/仅可录入/占位提示）集中维护，避免每个页面各写一遍下拉逻辑 |

## 5 收获与不足
**收获**：
- 用 CSS 复刻 95/98 视觉（外凸/内凹边框、点阵感标题栏）让我真正理解了"界面约束"也是需求的一部分；
- 组件库必须"业务无感"：把业务 API 调用全部挡在通用组件之外，页面组装才能像拼积木；
- 界面是需求的"最后一公里"：后端返回 `COURSE_FULL` 时，界面必须用学生能懂的中文说清"已满 10/10，请启用备选课程"，而不是抛出错误码。

**不足**：
- 课表页最初用整串 `HH:mm-HH:mm` 比较时段导致冲突标记失准（DEF-04），说明前后端时间格式必须写进接口文档；
- `Win95Button` 最初想兼容 `type="submit"` 导致登录页行为异常（DEF-05），教训是通用组件应聚焦单一交互语义；
- 界面走查项因缺少浏览器自动化工具未能全部在交付前执行完，只能在 10.16 运行检查现场按清单补齐。
