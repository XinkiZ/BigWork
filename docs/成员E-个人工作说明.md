## 1 职责概述
我负责教授从"选择授课"到"提交成绩"的整条后端链路：资格课程查询、选择/取消本学期课程班、
查看本人课程班选课名单，以及按学期录入与修改成绩。

## 2 具体工作项

### 2.1 选择授课
| 工作项 | 产出 | 说明 |
|--------|------|------|
| 资格课程 | `GET /api/professor/qualified-courses` | 授课资格来自遗留目录 `QUALIFY_TBL`（经成员F 的 `CatalogService` 读取） |
| 选择/取消授课 | `ProfessorService`、`POST`/`DELETE /api/professor/offerings/{offeringId}/select` | 仅当前学期；校验教授具备该课资格、时间不冲突、课程班未被他人选择 |
| 归属校验 | `ProfessorService` | 教授只能操作本人课程班；非法课程班返回 404/409 |

### 2.2 选课名单
| 工作项 | 产出 | 说明 |
|--------|------|------|
| 名单查询 | `GET /api/professor/offerings/{offeringId}/roster` | 展示本人课程班的选课学生与成绩；非本人课程班拒绝并给出无权限提示 |
| 按学期查询授课 | `GET /api/professor/offerings?semesterId=` | 迭代 2 起支持按学期查询本人授课列表（默认当前学期），取代旧 `/offerings/previous` 固定口径 |

### 2.3 成绩录入与修改
| 工作项 | 产出 | 说明 |
|--------|------|------|
| 批量录入 | `GET`/`PUT /api/professor/offerings/{offeringId}/grades` | 以表格批量提交 A/B/C/D/F/I；支持留空（暂不录）与后续修改 |
| 权限 | `ProfessorService` | 仅授课教授可写本人课程班的成绩 |
| 可录入学期口径 | `ProfessorService.requireGradeableSemester` | 目标学期必须"已开始（startDate ≤ 今天）且早于当前学期"；晚于当前学期的学期拒绝（409）；无前序学期时无可录入学期（DEF-08/DEF-09） |

### 2.4 测试

## 3 关键设计判断
| 判断 | 理由 |
|------|------|
| 资格与时间冲突在"选择授课"阶段双重校验 | 同一时段课程班只能被一个教授选择，冲突发现越早越好 |
| 成绩写入按"课程班 + 学生"定位，不接收他人课程班 ID | 服务层归属校验兜底，控制器层第一道是角色注解 |
| "上一学期"改为"当前学期之前的历史学期" | 学期可由管理员新建/切换后，"上一学期"不再等同于"可录入的最近历史学期"，必须落成明确规则 |

## 5 收获与不足
**收获**：
- "资格 + 冲突 + 归属"三类校验让我理解了同一条业务规则要在不同阶段重复兜底的价值；
- 口径从"上一学期"演进到"当前学期之前的历史学期"（DEF-08/DEF-09）说明**相对时间概念必须落到明确规则**，否则系统支持多学期后必然出错。

**不足**：
- 最初把可录入判定写成"已开始且非当前学期"，没有与当前学期比较先后，导致当前学期是最早学期时仍会列出后续学期（DEF-09，用户反馈）；
- 教授授课列表最初只有"上一学期"固定口径，直到迭代 2 才改为按学期参数查询。
